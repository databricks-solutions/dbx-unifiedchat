Architecture Reference

AgentRx

An admin-facing agent that lives inside the multi-agent Genie app. It manages the knowledge base (which Genie Spaces the system can answer about), edits Genie Space configuration (benchmark/sample questions, column visibility), and analyses user feedback — driven by a LangGraph ReAct loop over a set of Databricks-native tools.

AgentRx runs in the same Python process as the main Genie super-agent but on its own graph and its own backend route — it is not part of the user-facing clarification → planning → SQL workflow. It is reached from the dedicated /agent-rx admin page in the chat UI.

1 · Request flow

A single admin request travels from the browser, through the Node/Express proxy, into the Python AgentServer, where the LangGraph agent runs and streams its reasoning back as Server-Sent Events (SSE).

2 · The LangGraph ReAct loop

AgentRx wraps LangGraph's prebuilt ReAct agent. create_react_agent compiles a real StateGraph with four nodes — __start__, agent (the model call), tools (a ToolNode that executes the bound tools), and __end__ — wired by a conditional edge out of agent (loop to tools when the model emitted tool calls, otherwise finish) and a tools → agent edge that closes the loop. Tools are bound once at construction:

# agent_rx_agent.py
from langgraph.prebuilt import create_react_agent

self.tools = tools or (
    ALL_GENIE_TOOLS # Genie Space discovery + editing (11)
    + ALL_KB_TOOLS # knowledge-base index management (4)
    + ALL_ETL_TOOLS # ETL / refresh triggers (3)
    + ALL_FEEDBACK_TOOLS # MLflow feedback analysis (2)
)
self._agent = create_react_agent(model=self.llm, tools=self.tools,
                                 prompt=AGENT_RX_SYSTEM_PROMPT)

Compiled graph (create_react_agent)

The conditional edge out of agent routes to tools while the model keeps requesting calls, or to __end__ (dashed) once it returns a final answer; tools → agent closes the loop.

Streamed SSE event types

tool_calltool name + args the agent decided to invoke
tool_resultthe JSON string the tool returned
finalthe synthesized markdown answer
errorsurfaced failure message

Each frame is data: {json}\n\n; the UI renders them as a live "ReAct trace" disclosure plus a "Result" panel.

Reasoning model: the loop's LLM is a Databricks Model Serving endpoint, configured by LLM_ENDPOINT_AGENT_RX (default databricks-claude-sonnet-4-5) and invoked through databricks_langchain.ChatDatabricks.

5 · How Genie-Space edits work (the round-trip)

The Genie API has no granular mutation endpoints. Every edit is a read-modify-write on the space's serialized_space JSON blob, performed by the shared _edit_space() helper:

GET /api/2.0/genie/spaces/{id}?include_serialized_space=true   # read + etag
   # → parse serialized_space, apply the mutation in memory
PATCH /api/2.0/genie/spaces/{id}  body={ serialized_space, etag }  # write

Concurrency-safe

On an etag 409 conflict, _edit_space() re-reads and re-applies the mutation onto the fresh snapshot — a concurrent edit is never clobbered.

API invariants

Benchmark / example / instruction lists are sorted by id and column_configs by column_name before write; text fields are wrapped as the API's list-of-strings.

Net-zero & validated

"Show" drops now-empty configs and no-ops when already visible; column names are checked against Unity Catalog so typos can't persist junk.

6 · Auth, permissions & config

Authentication

_get_auth() resolves a host + bearer header in order: DATABRICKS_HOST/TOKEN env → databricks.sdk Config() (Apps OAuth / service principal) → notebook/REPL context. In production this is the app's service principal.

Permissions

The genie_space app resource grants only CAN_RUN (query). Editing requires CAN_MANAGE, granted to the app SP at deploy time by the shared-infra job (grant_genie_space_manage), which verifies the grant by reading the ACL back.
